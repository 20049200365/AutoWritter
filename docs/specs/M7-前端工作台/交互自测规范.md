# M7 前端交互自测规范

> 上级文档：[../M7-前端工作台/SPEC.md](../M7-前端工作台/SPEC.md)
> 目的：规定 Agent 如何**自行**打开前端、逐项覆盖用户全部交互做真机测试，替代"等用户反馈"的被动模式。
> 适用范围：工作台全部页面（封面 → 书架 → 写作台 8 页签 + 对话栏 + 全局组件）的交互验收、改动回归、发版前全量走查。

## 1. 测试环境与启动

### 1.1 启动顺序（每轮测试前）

```powershell
# 1. 后端（托管 frontend/dist，读取磁盘，前端改动后无需重启后端）
cd d:\coding\AutoWritter\backend
.\.venv\Scripts\python.exe -m app          # 监听 127.0.0.1:8000

# 2. 前端（改动后必须重新构建，dist 由后端托管）
cd d:\coding\AutoWritter\frontend
npm run build

# 3. 访问入口
#    http://127.0.0.1:8000   → 主应用（封面 → 书架 → 工作台）
#    http://127.0.0.1:8123/  → cover-demos/ 静态对比页（python -m http.server 8123）
```

### 1.2 测试代理：browser-use MCP（唯一真机手段）

环境内已注册 `browser-use` MCP（16 个工具），驱动本机 Chrome。按能力分四组：

| 类别 | 工具 | 用途 |
|---|---|---|
| 导航 | `navigate_page` / `select_page` / `list_pages` | 打开/切换/刷新页面；`ignoreCache:true` 强制绕缓存 |
| 读取 | `take_snapshot`（a11y 文本树，带 uid）/ `take_screenshot` / `list_console_messages` / `list_network_requests` | 断言 DOM 文本、抓 JS 报错、验证 API 请求 |
| 操作 | `click(uid)` / `fill` / `hover` / `press_key` / `drag` / `upload_file` / `wait_for` | 真实点击/输入/按键 |
| 脚本 | `evaluate_script`（在页面执行任意 JS，返回 JSON） | 几何断言、合成事件、状态读取——**最常用** |

**推荐操作模板**：进入工作台分成两步（先点「进入书架」等 1.2s，再点「继续写」等 2.5s，用 `evaluate_script` 内 `el.click()` + 延时），避免 `click(uid)` 在动画期超时。

### 1.3 已知环境限制（务必规避，否则误报）

| 限制 | 表现 | 规避 |
|---|---|---|
| **ResizeObserver 回调不触发** | observe 后连初始回调都不执行（已实测） | 宽度类断言直接用 `offsetWidth`；形态切换依赖 App 传 `chatW` prop |
| 浏览器缓存旧 JS | 页面加载旧 hash 的 bundle | 每次先 `navigate_page(ignoreCache:true)` 或 hard reload |
| 视口窄（≤1100px 时对话栏走媒体查询 340px） | 宽形态（≥520px）不生效 | 断言前先拖宽对话栏（见 §4.4 CH-3）或读实际 `offsetWidth` |
| 封面/书架动画时序 | 点击后元素未即时渲染 | 脚本内 `await setTimeout(900~2500ms)` 后再断言 |
| 截图文本不可读 | 当前模型无法从截图读内容 | 视觉断言改用几何量（位置/宽度/computedStyle），截图仅留档 |
| `click(uid)` 偶发超时 | 5s 不返回 | 改用 `evaluate_script` 内 `el.click()` + 延时轮询 |
| 原生 `confirm()` 阻塞 | 删除类操作弹系统框，MCP 无法点 | 用 `evaluate_script` 覆盖 `window.confirm=()=>true` 后触发 |
| SSE 流式靠真模型 | 无 KEY 时流式用例走 FakeProvider 或跳过 | 流式用例标注 [真模型]，无 KEY 则跳过并记录 |

## 3. 断言方法库（测试"怎么验"）

所有断言尽量用 `evaluate_script` 一次性返回 JSON：

```js
// 通用探针：量几何 + 取文本 + 查 class
() => {
  const g = (s) => { const n = document.querySelector(s); return n ? n.getBoundingClientRect() : null }
  return {
    colChat: g('#colChat'), sessCol: g('.sess-col'), curBar: g('.cur-bar'),
    drawerOpen: !!document.querySelector('.chat-drawer.open'),
    msgs: document.querySelectorAll('.msg').length,
  }
}
```

| 方法 | 适用 | 示例断言 |
|---|---|---|
| 存在性 | 元素是否渲染 | `!!document.querySelector('.sess-col')` |
| 文本 | 内容正确、无泄漏 | `.textContent.contains('章节')`；正文页无 `**加粗**` 残留 |
| class 态 | 状态是否切换 | `.tag.on` / `.toolcard.open` / `.think.open` / `.chat-drawer.open` |
| disabled | 按钮可用性 | 「落笔」空输入 `disabled` |
| 几何 | 布局/对齐/不重叠 | 两栏 `getBoundingClientRect()` 的 x+w 不交叉 |
| 计数 | 列表增删 | `.sess-item` 数量变化；卡片数 == 项目数 |
| 滚动 | 内容区滚动 | `scrollHeight > clientHeight` 且 scrollTop 沉底 |
| 网络 | API 是否发出 | `list_network_requests` 里 POST /sessions/…/chat 出现 200 |
| console | JS 报错 | `list_console_messages` 无 `error`/`pageerror` |
| localStorage | 持久化 | `ns.chatW` 存在且为数字 |
| confirm 覆盖 | 弹系统框的删除 | `window.confirm=()=>true` 后点击 |

## 5. 缺陷闭环（发现 bug 后）

1. **记录**：在 §4 对应编号下记现象 + 复现步骤 + 环境事实（对话栏宽度、视口、console 报错文本）
2. **定位**：读相关组件源码，对照预期找根因
3. **修复 + 构建**：改代码 → `npm run build`
4. **复验**：重跑该用例 + 相邻用例（如改布局则重跑 CH-3~CH-5 全部几何断言）+ 冒烟路径
5. **沉淀**：修复中发现的通用坑（布局重叠、环境限制）追加到 §1.3 或 E9 式禁止清单
