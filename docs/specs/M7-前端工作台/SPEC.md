# M7 前端工作台 — 模块 Spec

> 版本：v0.1（待审批）｜ 依赖：M6 的 OpenAPI/SSE 契约（前期对 Mock 开发）
> 职责：七大模块页面 + 章生成工作台 + Skill 管理 + 偏好档案页；划选编辑（Tiptap）；命令面板；设计令牌迁移
> 对外契约：◆ 按 M6 OpenAPI / M3 SSE 契约开发，前端不发明接口

---

## 1. 目标与边界

### 1.1 目标
1. 视觉与交互**对齐 `前端模板参考` Demo**（task.txt 为行为基准），设计令牌全量迁移
2. 落实用户红线：**所有文字内容所见即所得可编辑**，任何模块无只读视图
3. 消费 M6 REST + M3 SSE 契约，把两阶段生成、上下文账本、Skill 注入等机制完整可视化
4. 前期对 Mock 开发（MSW 按 M6 OpenAPI 捏），M6 就绪后逐页对接

### 1.2 边界
- 不做接口发明：请求/响应形态一律照 M6 OpenAPI；发现契约缺口走契约变更流程，不私自定义
- 不做业务计算：统计数字、回收率等一律读 `/stats` 与列表接口，前端不硬算
- Demo 的数据是 mock，本项目全部真数据——Demo 的"诚实说明条"不再适用

## 3. 设计令牌迁移（Demo task.txt §2）
- 色彩令牌全量迁移：纸底 #f6f1e6 / 卡片 #fbf8f0 / 墨色三阶 / 印章红 #a8433a（仅关键动作与当前态）/ 五色辅助
- 字体分工：宋体系（界面与正文）、楷体（引文/批注/提示语三类专用）、等宽（数字/章号/工具名）；数字 tabular-nums
- 质感细节至少四项：SVG feTurbulence 纸纹、书脊封面缩略、SVG data-URI favicon、边标签描边光晕、弹层 backdrop-blur
- 正文排版：16~17px、行高 2.0~2.1、段首缩进 2em、单栏 700~780px 居中；首字下沉防拆词规则照 Demo

## 4. 页面清单（10 页）

### 4.1 既有七模块（对齐 Demo §3）
| 页面 | 关键实现 |
|---|---|
| 1 书架 | 新建表单（题材/人称/基调）、删除 5 秒撤销 Toast、空态引导 |
| 2 Agent 对话 | 消息三段结构（思考折叠→工具卡片→正文）；流式光标 + 停止生成；快捷指令 chip；输入区上下文徽标；事件消费见 §5 |
| 3 正文 | 阅读态（§3 排版）/ 编辑态（Tiptap）；划选操作条；改写对照卡片（采纳替换/放弃/再来一次）；空章态显示大纲节拍 + 起草入口 |
| 4 实体关系图 | d3-force **实体图**：节点 = 人物 + 世界观实体（按类型颜色/图标 + 类型过滤开关）；边类型**自由文本**（常用类型专属配色，自造类型按名称哈希取色，图例动态生成）；拖拽局部加热；超长名截断 + title；点击节点展开写作导向档案 |
| 5 大纲与伏笔 | 三级树（计划/已写分表呈现）、章节挂载下拉（assign_outline）、中间插章、状态循环切换；伏笔四态 + 回收率 + 跨度预警；**回收操作纯用户驱动**；一致性巡检报告页 |
| 6 世界观 | 分类导航 + 卡片网格 + 词条编辑；写作引导「什么事不能做，做了会怎样」 |
| 7 时间线+看板 | 多轨横向时间线（轨道开关、锚点分隔、左侧留白不遮挡）；四种 SVG 图表全部读 stats 接口 |

### 4.2 新增三页
| 页面 | 关键实现 |
|---|---|
| 8 章生成工作台 | 流水线可视化（对齐 SSE 事件序列）：**细纲确认编辑器**（所见即所得，AI 提议显式标注「提议」徽标，保留=指示、删除=拒绝）→ 生成流式 → 评审雷达图与意见 → 接受/驳回（驳回标签含「情节方向不对」）→ 轮次版本对比；`context_ready` 账本卡片（"本章 AI 看到了什么"，逐条展开 + Skill 徽标） |
| 9 Skill 管理 | 列表/启用开关/CodeMirror Markdown 编辑/从预置模板复制；热切换即时生效 |
| 10 偏好档案 | 画像可视化（喜好/雷区/权重滑杆）、事件时间线、手动修正入口、版本回滚 |

## 5. SSE 事件 → UI 映射（对齐 M3 §5.1，11 种事件逐个消费）
| 事件 | UI 呈现 |
|---|---|
| progress | 工作台阶段条（装配/细纲/扩写/评审）高亮切换 |
| context_ready | 账本卡片渲染：材料清单逐条展开 + Skill 徽标 + token 汇总 |
| thinking | 思考气泡增量渲染（生成中展开带脉冲，结束自动收起，箭头方向与状态一致） |
| tool_call / tool_result | 工具卡片状态机（等待→转圈→带勾），完成可展开返回内容；预置历史消息的工具卡必须"完成"态 |
| plan_ready | 细纲填入确认编辑器，等待用户操作 |
| token | 正文逐字渲染 + 闪烁光标 |
| review | 评审雷达图 + 分级问题清单 |
| snapshot | 重连恢复：按快照重建当前呈现再续流 |
| done / error | 收尾态；error 按 resumable 显示「续跑」或「重试」 |

## 6. 所见即所得编辑（红线落地）
- 正文：Tiptap；划选操作条（批注 / 润色 / 精简 / 扩写 / 改人称 / 与 AI 谈这段）→ 调 `/rewrite` → 对照卡片；采纳经 `/commit` 留版本
- 批注锚点：offset + quoted 原文快照（锚点漂移兜底，对齐 M1 annotations）
- 结构化内容就地编辑：大纲节点行内编辑、人物卡/词条弹窗表单、伏笔状态操作、时间线事件编辑、Skill Markdown、画像字段
- 巡检规则：任何文本字段在 UI 上无编辑入口即判不合规（E2）

## 7. 全局交互（Demo §6 继承）
⌘K 命令面板（跨作品/章节/人物/设定/伏笔/会话检索，类型标签）、破坏性操作全撤销（Toast 带按钮，原位还原）、每个空态带下一步动作、Esc/⌘Enter 快捷键、窄屏（<1000px）折叠次要栏。

## 9. 端测流程（三层，含大模型自主驱动）

### 9.1 第一层：脚本化 E2E（Playwright，确定性，每次提交跑）
固定用户旅程用例：建项目→建大纲→生成章（mock SSE）→细纲确认→接受→统计联动→删除撤销；每个里程碑追加对真后端的端到端用例。

### 9.2 第二层：LLM 驱动的浏览器端测（大模型自主操作）
大模型经浏览器控制工具（Browser Agent）**真实打开前端、自主点击/输入/导航**，按清单执行验收并产出报告：
- **触发时机**：M7 里程碑收尾、每次发版前各跑一次（有成本与非确定性，不进每次提交）
- **执行内容**：E 系列验收逐项操作验证 + E9 禁止清单 12 条逐项目视 + 指定场景截图与 Demo 截图比对
- **场景清单**（对齐 Demo task.txt §8，至少 13 个）：书架、七大模块各一张、新建项目弹窗、删除确认弹窗、流式生成中间态、改写对照卡片、命令面板、空项目对话（§五必过）、细纲确认与账本卡片、生成工作台全流程、1000px 与 760px 窄窗、撤销 Toast 出现与生效
- **辅助手段**（照 Demo 验收协议）：注入 JS 错误捕获横幅抓前端异常；截图前注入禁用动画，避免把动画中间帧误判为缺陷；截图后逐张打开检查，不止看文件生成成功
- **产出**：端测报告 = 场景清单通过/失败 + 截图证据 + 缺陷清单（现象/原因/修法，对齐 Demo 交付格式）

### 9.3 第三层：缺陷闭环
端测发现缺陷 → 修复 → 重跑脚本化 E2E + 重截相关场景复验 → 更新报告；反复到清单全绿为止。
