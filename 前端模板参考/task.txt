任务：AI 小说创作助手 · 单文件前端原型
你要交付一个自包含的单文件 HTML 前端原型：一个面向中文长篇小说作者的 AI 创作助手工作台。所有数据为虚构 mock，仅存于内存，无后端、无网络请求、无 localStorage。

这份文档是规格书，不是灵感提示。其中标注「必过」的条目会被逐条验收；标注「禁止」的是已在同类实现中真实出现过的缺陷，不要重犯。

一、交付形式与工程约束
产物：一个 .html 文件（建议命名 novel-studio.html），双击可在 Chrome / Safari 打开即用。零构建、零依赖、零外部资源——不得引用 Google Fonts、CDN、图标库，全部字体走系统字体栈，图标全部内联 SVG。离线必须完全正常。
开发方式（有 shell 权限时必做）：拆成三个源文件开发，再用脚本内联成单文件：
src/shell.html — HTML 骨架 + 全部 CSS，末尾留 <script src="data.js"></script><script src="app.js"></script> 两行占位
src/data.js — mock 数据层 + Agent 回复模板
src/app.js — 状态、渲染、动作分发
tools/build.py（或 .js）— 读三个文件、node --check 两个 JS、把 JS 内联进占位处 内联前必须检查 JS 中不含 </script，否则脚本块会被提前截断。
可测试性（必过）：JS 中所有触碰 DOM / window 的顶层语句都用 typeof document !== 'undefined' 守卫，并在文件末尾导出纯函数供 Node 单测：

if (typeof module !== 'undefined' && module.exports)
  module.exports = { md, route, compose, seedData, esc, wordCount };
验收方式：把 <script> 块正则抽出存为 .cjs，require() 后直接调用这些函数必须不报错。
代码组织：事件用委托 + 动作分发表（data-act 属性 + 一张 ACT 映射表），不要在每次渲染后逐个 onclick 重新绑定。
规模参考：CSS 约 500–700 行，数据层 700–1000 行，逻辑层 1000–1500 行。宁可多写数据也不要模块做浅。
二、视觉规范（锁定，不要自由发挥）
主题固定为中式纸感书房：米白纸底、朱红印章色、墨色文字，克制、安静、长时间阅读不刺眼。禁止科技蓝、渐变紫、玻璃拟态、霓虹。

色彩令牌（用 CSS 变量，数值可微调）

纸底 #f6f1e6   卡片 #fbf8f0   次级底 #f0e8d6   更深底 #e9dfc8
墨色 #2f2a22   次级墨 #5c5548  弱墨 #8d8574
描边 #e3d9c4   重描边 #d3c7aa
印章红 #a8433a（主强调，仅用于关键动作与当前态）
辅助色（限用于分类/状态区分）：青 #40635c、赭 #b98a45、紫 #7c5f8f、叶绿 #6f8f62、铁灰 #55504a
字体分工（必做）

--serif: "Songti SC","STSong","Noto Serif SC","SimSun",serif   /* 界面与正文 */
--kai:   "Kaiti SC","STKaiti","KaiTi",serif                     /* 引文、批注、氛围文案 */
--mono:  "SF Mono",ui-monospace,Menlo,monospace                 /* 数字、章号、工具名 */
数字统一 font-variant-numeric: tabular-nums。楷体只用于「引用的小说原文」「AI 的旁批」「提示语」这三类，不要滥用。

质感细节（必做至少四项）
纸纹：用内联 SVG feTurbulence 生成极淡噪点铺满全屏（opacity ≤ .5，pointer-events:none），不要用图片。
书脊封面：项目列表里每本书用一个带内阴影的色块 + 书名首字（楷体）当封面缩略图。
SVG data-URI favicon（一个印章方块 + 一个字）。
SVG 里的文字标签用 paint-order:stroke; stroke:<纸底色>; stroke-width:4px 做描边光晕，让标签压在连线上仍可读——不要在标签下垫不透明矩形。
弹层遮罩用 backdrop-filter: blur(3px)。
正文排版（阅读体验是这个产品的门面）
正文字号 16–17px，行高 2.0–2.1，段首 text-indent:2em，段间距 1em 以上，字色比界面文字略暖（如 #3b342a），单栏宽度 700–780px 居中。

首字下沉（drop cap）如果做，必须先判断首字是否会拆开一个双字词（如「酒馆」被拆成「酒 / 馆」就是错的）。安全做法：只在首字为单字成词或标点后再启用，或干脆改用「首行整行加粗 + 首字放大 1.4 倍不浮动」。宁可不做，也不要拆词。
三、信息架构
三栏结构：项目栏（书架）→ 上下文栏（随模块变化）→ 主区。主区顶部有项目名 + 模块切换 + 实时统计条。

七个模块全部必做，每个都要有真实内容，不允许出现「功能占位」「敬请期待」：

模块	核心职责
1. 项目库 / 书架	新建、删除、切换作品
2. Agent 对话	会话管理 + 数据驱动的创作问答
3. 正文	章节阅读 与 编辑（两者都要，见下）
4. 人物关系	力导向关系图 + 人物档案
5. 大纲与伏笔	卷章结构 + 伏笔埋收追踪（可写）
6. 世界观设定库	分类词条库
7. 时间线 + 创作看板	多轨事件时间线；字数/进度/张力图表
模块 1 · 项目库
新建：弹窗表单至少含 书名 / 题材（下拉）/ 一句话简介 / 目标字数 / 叙事人称 / 基调（多选）。创建后直接进入该项目，并自动生成一个引导会话（内容必须引用用户刚填的简介，见 §五）。
删除：二次确认弹窗要说清代价（「共 N 章、N 字、N 个会话」）。必过：删除后弹出可撤销提示（Toast 带「撤销」按钮，5 秒内点击能原位还原）。禁止写「此操作不可撤销」来回避实现。
删光所有项目后要有得体的空态 + 「新建」入口，不能白屏或报错。
模块 2 · Agent 对话
会话列表：新建、删除（同样带撤销）、搜索、按更新时间展示；首条用户消息自动成为会话标题。
消息流：用户气泡右对齐；AI 消息左侧头像 + 三段结构 思考过程（可折叠）→ 工具调用卡片 → 正文答案。
思考过程：生成中默认展开并带脉冲动画，生成结束自动收起；折叠箭头方向必须与展开状态一致（展开朝下）。
工具调用卡片：显示工具名（等宽字体）、入参摘要、状态（等待 / 调用中带转圈 / 完成带勾），完成后可展开看到返回内容。返回内容必须是从当前项目真实统计出来的（见 §五）。
流式输出：逐字增量渲染 markdown，末尾闪烁光标，提供「停止生成」。
必过：预置的历史会话里，工具卡片状态必须是「完成」且能展开看结果，不能停在「等待」。
必过：生成过程中切换模块或切换会话，那条半截消息必须被补全或明确标记，不能永远停在半截 + 残留光标。
输入区：多行自动增高、Enter 发送 / Shift+Enter 换行（提示文字要写出来）、发送按钮带文字标签（如「落笔」）而非纯图标、下方显示当前上下文徽标（当前章 / 人物数 / 伏笔数）。
提供 4–6 个快捷指令 chip。
模块 3 · 正文（阅读 + 编辑）
两种形态都要，可用一个开关切换：

阅读态：按 §二 的排版规范呈现，顶部卷标签 + 章标题 + 元信息（字数 / 状态 / 更新时间），底部「上一章 / N/M / 下一章」翻章器。
编辑态：可直接改标题与正文，字数实时更新；选中一段文字后出现操作条（润色 / 精简 / 扩写 / 改人称），点击后展示改写前后对照卡片，带「采纳替换 / 放弃 / 再来一次」。
改写必须是真实的字符串变换，且必过：对任意选中文本都要产出可见变化。词典替换命中不了时要有兜底策略（例如「把最长的句子从中间的逗号切开」实现短句化，或「删掉一处比喻从句」实现精简），不允许出现「未检测到可改动处」这种空转结果。
无正文的章节要有空态：展示该章大纲节拍 + 「让 Agent 起草本章」（点击后把本章节拍带入对话输入框）+「我自己写」。
必过：字数口径唯一且自洽。 要么章节正文全量写出（字数=实算），要么显式区分「完整章节 N 字」与「编辑区节选 M 字」两个数字并在界面上标注是节选。禁止出现侧栏显示 9,080 字、页脚显示 583 字却毫无解释的情况；编辑时也要按增量正确累加，不能把总字数抹成节选长度。
模块 4 · 人物关系
力导向图：自己实现简易物理迭代（斥力 + 弹簧 + 阻尼 + alpha 衰减 + requestAnimationFrame），节点可用指针拖拽，拖动时局部重新加热。
关系按类型用不同颜色 + 不同虚线样式区分（如 血缘 / 亲和 / 对抗 / 秘密 / 师徒 / 造物），图例常驻。
连线中点显示关系标签（用 §二 的描边光晕保证可读）。
点击节点：高亮该节点、淡化无关支线、右侧展开人物档案。档案字段必须是写作导向的，至少包含：外在形象 / 表层动机 / 深层秘密 / 人物弧光 / 首次出场章 / 出场章数 / 关系列表。「想要什么」与「真正需要什么」必须是两个互相拉扯的字段。
必过：图必须撑满容器且节点分布均衡，不允许所有节点挤在中间一小团、上下留大片空白。初始坐标给合理布局，物理只做微调。
必过：姓名超长（如「母亲（未定名）」）不得溢出节点圆形，需截断 + <title> 保留全名。
模块 5 · 大纲与伏笔
数据模型必做区分：volume.items[] 是大纲计划（可有 24 章，每章一句节拍 + 状态），chapters[] 是已写稿件（只有少数几章有正文）。两者不要混成一张表。
卷章结构视图：卷头显示卷名 / 章节范围 / 一句话概要；章行显示章号、章名、节拍、状态徽标、张力值。点击章行可循环切换状态（构思→大纲→草稿→待修→定稿）。
伏笔追踪视图：
四态模型（已埋设 / 部分揭示 / 已回收 / 悬空未规划）+ 重要度权重（如三点表示）。
每条显示「埋设第 X 章 → 回收第 Y 章」及跨度；跨度过大（>12 章）标黄提示读者已遗忘风险。
顶部统计卡 + 回收率进度条。
必过：伏笔是可写的——能标记已回收 / 撤销回收、能新增伏笔（弹窗表单，不填回收章则自动标为「悬空」）。
必过：状态改变后，风险提示条、回收率、模块角标、看板数字全部联动更新。
一致性巡检：一个按钮，跑一段带进度的伪扫描，输出分级问题清单（高 / 中 / 低）。清单必须由真实数据算出，至少覆盖：悬空伏笔、跨度过长的伏笔、计划回收章已定稿但伏笔仍未回收、连续三章张力接近的节奏平台期。禁止硬编码结论。
模块 6 · 世界观设定库
分类导航（地理 / 势力 / 力量体系 / 器物 / 名词 / 习俗），卡片网格，点击展开完整词条。每条设定必须能影响情节，不要写百科式空话——好的设定条目会解释「什么事不能做，做了会怎样」。

模块 7 · 时间线 + 创作看板
时间线：横向滚动，多轨道（主线 + 若干人物线 + 伏笔埋收线），轨道可开关，时代锚点做分隔线，事件节点可点击看详情并跳转对应章节。必过：最左侧的时代锚点和最早的事件不得被固定的轨道名遮挡（给左侧留白后再映射坐标）。
看板：手写 SVG 图表，至少四种——日更字数柱状图（含断更日空档）、章节张力折线（已定稿点实心）、目标进度环形、人物出场频次条形。数据全部由当前项目实时计算，改一条伏笔或一章正文，数字要跟着变。必过：坐标轴刻度标签必须留出独立留白，不得压在柱子或曲线上。
四、Mock 数据要求
三个作品，处于三个不同阶段：一部连载中（内容最厚，作为主样本）、一部刚起步、一部仅筹备（用来展示各模块的空态）。题材要互相区别（如 悬疑 / 玄幻 / 科幻 / 日常 任选三）。
主样本的体量下限：≥ 20 章大纲条目（其中 3–5 章有真实正文）、≥ 8 位人物、≥ 10 条关系、≥ 8 条伏笔、≥ 12 条世界观词条、≥ 15 个时间线事件、≥ 3 段预置对话。
伏笔必须互相咬合：至少要有一组「三处不同章节的细节 → 指向同一个真相」的结构，并且这组细节要真的出现在你写的正文里、出现在人物的秘密字段里、出现在时间线上。评审会交叉检查这种一致性。
正文要真的像小说，不是设定说明。短句、动作带情绪、少用副词，人物说话要有各自的声口。总计写出 2000 字以上的真实正文。
界面上要有一处诚实说明：数据为虚构演示，仅存于内存，刷新即重置。
五、Agent 模拟引擎（本任务最容易失败、也最要紧的一环）
必须做成数据驱动，不是预写答案。架构：


route(text)                    // → intent，至少 8 类 + 兜底
compose(project, intent, text) // → { think:[...], tools:[...], answer }
硬性规则（逐条必过）：

answer / think / tools[].result 中出现的任何人名、章名、卷名、伏笔名、数字、题材，都必须从 project 参数里读出来。禁止在回复模板里硬编码任何具体作品的专有名词。
空项目必过测试：新建一个空白作品（0 章正文 / 0 人物 / 0 伏笔），依次触发全部 intent。要求：
回复中绝不出现任何预置样本作品的专有名词；
每个 intent 都走「引导分支」，说清当前缺什么、下一步填什么（例：「《书名》还没有登记伏笔，推荐先埋两条：…」）；
工具卡片的返回值也要如实反映空状态（例：「检索伏笔清单 共 0 条」）。
这是最常见的翻车点：预写一段漂亮的散文式回复，换个项目就在谈论另一本书的人物，同时界面角标还写着「0 伏笔」，自相矛盾。

题材感知：至少三种题材下，「续写」给出的草稿在语气、意象、句式上明显不同。
实体感知：用户提到某个人物名时，要取出该人物的真实档案作答；提到某章时取该章。
至少覆盖这些 intent：打招呼/能力介绍、续写、人物分析、伏笔梳理、大纲节奏诊断、润色建议、卡文疏导、取名，外加兜底。
兜底回复也要有信息量：报出当前项目真实的产出缺口（几章待写、几条伏笔悬空、节奏平台期在哪）。
细节加分：代词按人物性别选择；引用正文时用楷体块引用；给出的建议要能落到具体章号。
六、状态与交互深度
全内存状态，单一 state 对象；禁止使用 localStorage / sessionStorage。
所有破坏性操作（删项目 / 删会话 / 删章节）都必须支持撤销，通过带「撤销」按钮的 Toast 实现，还原时要回到原来的位置（数组索引）。
提供全局命令面板（⌘K / Ctrl+K）：跨作品 / 章节 / 人物 / 设定 / 伏笔 / 会话统一检索，方向键选择、回车跳转、Esc 关闭，结果带类型标签。
键盘：Esc 关弹层 / 退出专注模式；⌘Enter 发送。
每一个空态都要有明确的下一步动作按钮，不能只写「暂无数据」。
Toast 位置不得遮挡输入区或快捷指令行。
七、明确禁止（都是真实出现过的缺陷）
章号列宽度不足导致「第 10 章」折成两行——章号用等宽字体 + 零填充（CH.10）或给足 min-width。
display:flex 的子元素被默认 align-items:stretch 拉高，圆角徽标变成大椭圆并被容器裁切——记得 align-self:flex-start 或给容器设 align-items。
列表预览直接显示原始 markdown（###、** 泄漏）——剥离函数要把 # 也算进去。
内联 SVG 图标没有尺寸约束，在某些容器里被撑到几百像素——加一条全局兜底 svg{width:14px;height:14px;flex:none}，再对图表 / 关系图容器内的 SVG 单独覆写为 width:100%;height:auto。
窗口收窄到 900px 以下时三栏固定宽把正文压成每行几个字——给中间栏设可折叠或 min-width，窄屏下隐藏次要栏。
首字下沉把中文双字词拆开（见 §二）。
字数出现两个互相矛盾的口径且无解释（见 §三·模块 3）。
关系图边标签与节点副标题重叠成一团。
折叠箭头方向与展开状态相反。
预置消息的工具卡片停在「等待」状态。
图表轴标签压在数据图形上。
用「此操作不可撤销」的文案回避撤销功能的实现。
八、自检与验收协议（必做，并在最终答复里报告结果）
有 shell 权限就按下面做完整验收；没有就按 §七 + 所有「必过」条目逐条人工核查，并如实说明未能自动验证。
